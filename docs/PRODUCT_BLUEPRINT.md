# CREOVA — Product Blueprint

## Starting point

CREOVA is a new project being built from zero. There is no existing application implementation to continue or import.

## Product definition

CREOVA is an **Active Skill Execution Network**. It helps people turn ideas, challenges, and skills into real work; build on one another's contributions; and show evidence of progress.

The core loop is:

**ACTION → EXECUTION → EVOLUTION → PROOF → DISCOVERY**

## Core concepts

- **Anchor:** the starting contribution: an idea, challenge, skill, or project.
- **Iteration:** a contribution that executes, improves, remixes, or extends an Anchor or another Iteration.
- **Execution Tree:** the traceable relationship between an Anchor and all its descendant Iterations.
- **Proof:** media, notes, milestones, or other evidence attached to a contribution.

## Product principles

1. Creation and execution take priority over passive consumption.
2. Every account can create Anchors and Iterations.
3. Preserve attribution and lineage throughout an Execution Tree.
4. Make it easy to discover work by skill, action, and potential next step.
5. Avoid making follower counts and likes the primary measure of value.
6. Design for mobile first, including modest Android devices and slower connections.
7. Build real functionality; label unfinished features honestly.

## Initial product scope

1. Account registration, sign-in, and onboarding.
2. User profiles and skills.
3. Create and manage Anchors.
4. Create Iterations from Anchors or existing Iterations.
5. Browse a discovery feed and inspect Execution Trees.
6. Search people, skills, Anchors, and Iterations.
7. Attach proof/media to contributions.
8. Notifications and direct messaging.
9. Block, mute, report, moderation, and appeals.

## Safety and trust

- Users can block and mute accounts.
- Users can report contributions and accounts.
- Moderation actions must be permission-checked and auditable.
- Held or removed content must not leak through feeds, search, profiles, or tree views.
- Appeals must be reviewable, with outcomes recorded.
- Notifications must respect privacy and user preferences.

## Delivery approach

- Start from a clean repository and build in small, testable stages.
- Work on feature branches; do not use main for unfinished work.
- Establish the app foundation and data model before implementing feature screens.
- Use free-tier-friendly services where practical; do not activate paid services without approval.
- Do not claim tests, deployments, or integrations succeeded unless they were actually run and verified.

## Brand direction

The selected visual concept is a beautiful planet Earth in deep space, surrounded by a metallic-gold orbital form. The final launcher icon should be a clean, recognizable symbol without text. The image asset still needs to be added separately.
